2. PROBLEM 1: BLANK BUBBLES PAR FALSE '8' DETECTION KYU HO RAHA THA?
====================================================================================================

[ROOT CAUSE ANALYSIS]:
1. Printed Ink Density of Digit '8':
   - Numerical matrix (0-9) me har circular bubble ke andar printed digit hota hai.
   - Digit '8' me 2 complete closed loops aur thick horizontal strokes hote hain.
   - Binarized / thresholded image me un-filled (blank) digit '8' bubble ke andar printed text aur 
     border milakar 43.0% se 48.0% dark ink pixels generate karte hain.

2. Outdated Threshold Configuration:
   - Config me `numerical_fill_threshold` 42.0% par set tha.
   - Jab student question ko blank chhodta tha, tab bhi empty digit '8' ka ink (44%-48%) is threshold 
     (42.0%) se zyada ho jata tha (`44% > 42%`).
   - Is wajah se scanner use student ka bhara hua mark samajh kar '8' detect karta tha aur visualizer 
     green circle draw kar deta tha.

3. The True Separation Gap:
   - Blank digit '8' text ink: Max 48.0%
   - Actual student pen/pencil fill: 82.0% se 98.0% (e.g. 92.9%, 95.4%, 98.0%)
   - Dono ke beech ~35% ka massive clear gap exist karta hai.

[THE FIX APPLIED]:
- `numerical_fill_threshold` ko 42.0% se badhakar **55.0%** set kiya gaya.
- Outcome:
  * Sabhi empty bubbles (max 48%) threshold se safely 7% niche hain -> ZERO False Positive.
  * Real student marks (82%-98%) threshold se 25%+ upar hain -> 100% Accurate Detection.

3. PROBLEM 2: 2-DIGIT ANSWERS ME UNITS ROW KYU MISS HO RAHI THI (Q25='30' -> '3', Q50='12' -> '1')?
====================================================================================================

[ROOT CAUSE ANALYSIS]:
1. Theoretical Spacing vs Physical Print Reality:
   - Old template assumption: Har question block me 4 rows (TH, H, T, U) ke beech uniform 18.0px spacing 
     aur base Y = [918, 1016, 1114, 1212, 1310] assume kiya gaya tha.
   - Physical Print Reality: Sheet par actual row spacing 17.3px hoti hai (0.7px difference per row).
   - Q21 (Row 1) par 0.7px ka farak notice nahi hota tha, lekin jab scanner 5th question (Q25/Q50) 
     tak pahunchta tha, toh accumulated vertical error **8 se 9 pixels** ban jata tha.

2. Units Row Shift Breakdown:
   - Actual Sheet par Units row (Row 3): Y = 1305 + 51.9 = **1356.9px**
   - Old Scanner Sampling Position:       Y = 1310 + 54.0 = **1364.0px** (+8px offset)
   - Sampling box (roi=14px, radius 7px) student ke marked bubble ke bilkul neeche land karta tha:
     * Q25 (Marked '30'): Tens ka '3' (Y=1338) 90.8% par detect hua, lekin Units ka '0' (Y=1355) 
       par sampling box shifted hone se sirf 42.9% fill aaya (< 55% threshold). Units drop ho gaya 
       aur answer sirf '3' bacha.
     * Q50 (Marked '12'): Tens ka '1' (Y=1338) 92.9% par detect hua, lekin Units ka '2' (Y=1354) 
       par sampling box shifted hone se sirf 39.3% fill aaya (< 55% threshold). Units drop ho gaya 
       aur answer sirf '1' bacha.

[THE FIX APPLIED]:
- Base Y Coordinates ko calibrate karke exact printed centers par align kiya:
  `t2_num_y = [917, 1014, 1114, 1209, 1305]`
- Row Offsets ko precise 17.3px spacing par set kiya:
  `t2_num_row_offsets = [0.0, 17.3, 34.6, 51.9]`
- Column X Coordinates ko sub-pixel center calibration diya:

  Chem Num:    [341, 366, 390, 414, 439, 463, 488, 512, 537, 561]
