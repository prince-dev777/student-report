- **NO AUTOMATIC PUSH OR PUBLISH:** Do NOT run `git push` or `electron publish` under any circumstances unless explicitly and directly instructed by the user.

- **NO ELECTRON BUILDS:** Do NOT run `npm run build`, `npx electron-builder`, or any script that builds the Electron app, UNLESS the user explicitly and clearly tells you to do so right at the moment of execution.
- **RELEASE RULES:** When explicitly asked to build/release, always strictly adhere to the procedures and naming conventions documented in `c:\Users\sawar\MyProjects\student-report\release_Rules.md`.

Always use `child_process.fork()` instead, as `fork` is specifically patched by Electron to seamlessly extract and execute scripts from inside ASAR archives, preventing `ENOENT` crashes in production builds.
- **OMR SCANNER PROTECTION RULE:** NEVER modify, touch, edit, refactor, or delete ANY files inside `server/omr_scanner/`, `C:\Users\sawar\MyProjects\omrScanner\`, or `server/omr_engine_v2.py` UNLESS the user explicitly and directly gives permission or instructs you to change the OMR scanner. Whenever ANY modifications are made to `server/omr_engine_v2.py` or `server/omr_scanner/`, you MUST ALWAYS recompile `omr_engine_v2.exe` via PyInstaller (`cd server && pyinstaller --noconfirm --onefile --collect-all omr_scanner omr_engine_v2.py` and copy `server/dist/omr_engine_v2.exe` -> `server/omr_engine_v2.exe`) BEFORE running `npx electron-builder`. Never allow production builds to bundle an outdated Python executable.

Zero mistakes from frontend to backend.
